## M1: 技術検証（Spike）

**目的**: 「答えを言わない」がプロンプトで本当に実現できるかを、UI なしで確かめる。
ここが崩れると製品が成立しないため、最初に潰す。

- [ ] OrcaRouter 疎通（`GET /v1/models` でカタログ取得、用途別モデル ID を確定 → Q-1）
- [ ] Diagnoser の構造化出力（JSON Schema 準拠）を CLI で実行
- [ ] Questioner に `focus_hints` だけを渡し、答えを漏らさず出題できるか検証
- [ ] LeakGuard の検出ルールを実装し、代表 20 ケースで検証
- [ ] 実際のエラー 10 件で、Lv1〜Lv5 を手動で通しでやってみる

**受け入れ条件**:
- 10 件中 8 件以上で、Lv1〜Lv5 のすべての生成文に答えの漏洩がない
- Diagnoser の原因特定が 10 件中 7 件以上で妥当

> **この段階で漏洩が止まらない場合**、Questioner に渡す情報をさらに削るか、
> 選択肢を LLM 生成ではなくテンプレート化する方向に設計を変更する。

## M2: MVP（コア体験の一気通貫）

**目的**: 「エラーを投げる → 段階的に問われる → 自力で気づく」を通しで動かす。

### バックエンド
- [ ] モノレポ初期化（pnpm workspaces + Turborepo）
- [ ] `packages/shared`: Zod スキーマ（API 契約）
- [ ] `packages/core`: 段階遷移ステートマシン / マスキング / LeakGuard（**単体テスト付き**）
- [ ] `packages/db`: Prisma スキーマとマイグレーション
- [ ] `packages/llm`: OrcaRouter クライアント + Diagnoser / Questioner / Judge
- [ ] `apps/api`: `POST /sessions`, `POST /answers`, `POST /hints`, `POST /conclusion`
- [ ] 匿名 ID Cookie ミドルウェア

### フロントエンド
- [ ] `apps/web`: エラー投稿フォーム
- [ ] 問答画面（質問カード / 選択肢 / 段階プログレス / ヒントボタン）
- [ ] 原因宣言フォーム

**受け入れ条件**:
- 実際のエラーを投げて Lv1〜Lv5 を通過し、原因宣言で `reached` 判定を受けられる

**MVP に入れないもの**: レポート / スコア / 履歴 / SSE / レート制限

## リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **LLM が答えを漏らす** | 製品価値が消滅 | M1 で最優先検証。役割分離 + LeakGuard + フォールバックテンプレートの三重防御 |
| **診断が外れる** | 見当違いの質問で学習にならない | `confidence` が低い場合は情報を補う質問に切り替える。レポートで「診断が外れていた」旨を正直に出す |
| **質問が退屈 / 冗長** | 離脱 | 段階を 5 つに固定し、1 段階あたり最大 3 問で必ず前に進める |
| **待ち時間が長い** | 離脱 | 診断を非同期化し Lv1 と並行。SSE で体感短縮 |
| **エラーに認証情報が混入** | 情報漏洩 | 保存前・送信前のマスキング（FR-13）を M2 の必須項目とする |
| **LLM コストが想定超過** | 運営不能 | 用途別モデル分離 + セッション単位のトークン上限 |
