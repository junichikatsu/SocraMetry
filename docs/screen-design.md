## 1. 画面一覧

| 画面 | 用途 | 対応 | 実体 |
|---|---|---|---|
| ログイン | 認証。メール + パスワード（+ 新規登録時は招待コード） | FR-31a | `#login` |
| 対話 | 3 ゲートすべて。**1 本のスレッドで進む** | FR-03〜FR-10 | `#view-chat` |
| ダッシュボード | 個人の集計と 5 軸レーダー | FR-24 | `#view-dashboard` |
| チャット一覧 | 過去セッションの一覧 | FR-24 | `#view-history` |

**ページ遷移は無い。** すべて 1 枚の HTML 内の表示切替で進む（ADR-012 / ADR-013）。

### 画面を分けなかった理由

3 ゲートを画面ごとに切り替える案は採らなかった。
Gate A（ヒント）→ Gate B（設問）→ Gate C（解説）は**同じ相手との一続きの会話**であり
（socratic-engine.md §1）、画面が切り替わるとその連続性が切れる。
スレッドに積み上げれば、前のヒントを読み返しながら次の設問に答えられる。

## 3. 画面項目定義

### 3.1 ログイン

| 項目 | 種別 | 必須 | 制約 | 備考 |
|---|---|---|---|---|
| メールアドレス | email | ✅ | 3〜254 文字 / 形式検証 | データストアのメインキー。小文字化して送る |
| パスワード | password | ✅ | 8〜200 文字 | scrypt（security.md §5） |
| 表示名 | text | 新規登録のみ ✅ | 1〜40 文字 | |
| 招待コード | text | 新規登録のみ ✅ | 1〜200 文字 | 公開 URL に無制限のサインアップを置かない |

> **#14 の本文にある「軽量案（招待コード = ログイン ID、パスワードなし）」は採っていない。**
> モック（`login-screen.png`）・設計書（requirements.md FR-31a / security.md §5 /
> scope-v0.1.md §4.2）・実装のいずれもメール + パスワード + 招待コードで一致している。
> 軽量案は PR #2 のコメントで**提案**された段階のもので、合意には至っていない。

### 3.2 対話（入力欄）

入力欄は**状態によって意味が変わる**。同じ場所を使い回すのは、
モックの構造（下部に 1 つの入力欄）を保つため。

| 状態 | 送信先 | プレースホルダ | 言語 / FW |
|---|---|---|---|
| セッション無し | `POST /v1/sessions` | デバッグ対象のコード、エラーログ… | 表示 |
| セッション進行中 | `POST /v1/sessions/{id}/conclusion` | 原因が分かったら、自分の言葉で… | 非表示 |
| 完了 | — | （無効） | 非表示 |

| 項目 | 種別 | 必須 | 制約 |
|---|---|---|---|
| 本文 | textarea | ✅ | 1〜20,000 文字。Enter で送信 / Shift+Enter で改行 |
| 言語 | select | | 事前定義リスト。既定「指定しない」 |
| フレームワーク | select | | 同上 |
| マスキングプレビュー | 読み取り専用 | — | 入力のたびに更新。**常時表示のパネル** |

### 3.3 ダッシュボード

`GET /v1/me/stats` の値のみ。**算出できない値は「—」と出す。ダミーで埋めない。**

| 項目 | 出典 |
|---|---|
| セッション数 / 累計時間 | `sessionCount` / `totalElapsedMs` |
| 到達内訳（A / B / C） | `gateDistribution` |
| 設問の正答率 | `correctRate`（設問に進んでいなければ null） |
| 直近スコア | `trend` の末尾 |
| 5 軸レーダー | `recentAxes` |

## 4. アクション定義

| 操作 | 起点 | 呼び出し | 条件 | 遷移 |
|---|---|---|---|---|
| ログイン | ログイン画面 | `POST /v1/auth/login` | — | 対話画面 |
| 新規登録 | ログイン画面 | `POST /v1/auth/signup` | 招待コード必須 | 対話画面 |
| エラー投稿 | 入力欄 | `POST /v1/sessions` → `POST /diagnose`（**待たない**） | セッション無し | Gate A |
| ヒント追加 | 行動ボタン | `POST /hints` | `actions.canRequestHint` | Gate A / B |
| 設問に進む | 行動ボタン | `POST /advance` | `actions.canAdvanceToQuestions` | Gate B |
| 設問に回答 | 選択肢 | `POST /answers` | 設問表示中 | Gate B 継続 / 終了 |
| 原因宣言 | 入力欄 | `POST /conclusion` | `actions.canDeclareConclusion` | 到達なら結果 |
| 解説を読む | 行動ボタン | `POST /reveal` | `actions.canReveal` | Gate C |
| 振り返り | 選択肢 | `POST /retrospect` | Gate C | 結果 |
| 結果表示 | 自動 | `GET /report` → `GET /cost` | 完了時 | 結果カード |

**どのボタンを出すかは、必ずサーバの `actions` に従う。**
クライアントに条件式を置くと、ゲート遷移規則（socratic-engine.md §7）が
2 箇所に分かれて必ずずれる。

### 4.1 不可逆な遷移の確認

「設問に進む」は**確認ダイアログを出す**（api-spec.md §3.4）。
Gate B に入った後に Gate A の評価は得られないため。

### 4.2 時間経過による Gate A → B（#20 / FR-07）

Lambda は定期実行を持てないため、**タイマーはクライアントに置く**。
発火条件はサーバにあり、クライアントが受け取るのは `session.autoAdvanceInMs`（残り時間）だけ。

| | 挙動 |
|---|---|
| 30 秒前 | スレッドに予告を出す。**黙って遷移させない** |
| 発火時に入力中 | 見送って 20 秒後に再判定（socratic-engine.md §7 の判断 3） |
| 発火 | スレッドに「時間が経ちましたので、設問に移ります」を出して `POST /advance` |

「入力中は時間条件を適用しない」はサーバから観測できないため、
**クライアントにしか実装できない。**

### 4.3 到達しなかった原因宣言の扱い

**設問には戻さない**（socratic-engine.md §4.3 / Q-15）。
これは `verdict: null`（判定を行わなかった）でも `not_reached` でも同じ。

画面は**サーバの `feedback` をそのまま出し、行動ボタンは `actions` に従う**だけにする。
理由ごとの案内はサーバの文面が持っているため、画面で言い足さない。

| サーバ側の分岐 | `feedback` の内容 |
|---|---|
| 短すぎる入力 | 「もう少し具体的に書いてみてください（10 文字以上）」 |
| 「わかりません」 | 「設問に戻って絞り込むか、解説を読むかを選べます」 |
| 診断が未完了 | 「内容を確認しています」＋ `202` で再送 |
| 診断が失敗 | 「到達判定ができません。解説の表示に進むことはできます」 |

> **「設問には戻しません」と画面に書かない。**
> Q-15 は**戻さないことが要件**であって、戻さないと宣言することではない。
> 戻される可能性があったこと自体が利用者には初耳で、書いた瞬間に不安を作る側に回る。
> 隣に「設問に進む」ボタンが並ぶ場面では、字面としても矛盾する。
>
> 同じ理由で、**設計判断の根拠を画面の文言に流用しない**。
> 根拠は設計書とコードのコメントに置く。

行動ボタンは押せるものが 1 つも無ければ出さない（空の枠を置かない）。
「押せるが何も起きない」ボタンは作らない。

## 5. 表示上の約束

設計書に根拠がある項目。**落とすと要件を満たさなくなる。**

| # | 約束 | 根拠 |
|---|---|---|
| 1 | 診断は投げっぱなし。セッション作成直後に `POST /diagnose` を撃ち完了を待たない | ADR-006 / NFR-P1 |
| 2 | `202` が返る間は同じリクエストを再送する | api-spec.md §3.5 |
| 3 | 「設問に進む」に確認を出す | api-spec.md §3.4 |
| 4 | ローディングは「先輩が考えている」表現。**進捗バーにしない** | ADR-007 |
| 5 | MOCK モードであることを画面に明示する | ADR-014 |
| 6 | スコアの算出根拠を必ず表示する。**総合点だけを出さない** | NFR-F1 |
| 7 | 「わかりません」で設問に戻さない | Q-15 |
| 8 | `textContent` のみを使う。`innerHTML` は使わない（lint で禁止） | security.md §7 |
| 9 | API は相対パスで呼ぶ | ADR-012 |
| 10 | 送信前にマスキング結果を表示し、**マスク済みテキストを送る** | security.md §3 |
| 11 | 外部ホスト（CDN・Web フォント）を読まない | ADR-012 |

### 5.1 Gate A の 5 軸は「参考値」と明示する

Gate A（自力解決）では**5 軸が全部同じ値になる**（実測 70/70/70/70/70）。
設問を 1 問も解いていないため、軸ごとに差がつく材料が存在しない
（evaluation-model.md §4.6 に既知の限界として記載）。

**§4.6 の案 B を採る**（#27 で決定）。

- 値は出す。ただし見出しを「5 軸スコア（参考値）」にする
- レーダーの線を**破線・灰色**にして、他のセッションと見た目で区別する
- 「軸ごとに差がつく材料がない」理由をその場に書く
- 成長率の算出には使わない

> 数値の意味が場合によって変わることを隠さない。
> それも「説明できない数値を評価に使わせない」（NFR-F1）の一部である。

### 5.2 出題対象外の軸（`null`）

`DEMO_MAX_STAGES` で段階数を絞ると、対象外の軸は `null` で返る。
**0 点として描かない。** 0 と同じに見せると「何もしていないのに 0 点」と読める。
レーダーは描かず、一覧に「対象外」と出す。

### 5.3 答えを出してよい場所

**Gate A・B のどの画面にも答えを出さない**（DoD #2）。
`revealedAnswer` を描画するのは**結果カードだけ**で、これはセッション完了後にしか作られない。
API 側でも Gate C 到達前の全応答に答えが含まれないことを機械的に検証している
（`apps/function/src/api.test.ts` の「答えが Gate C 到達前に漏れない（DoD #2）」）。

## 6. モックにあるが実装していないもの

**ダミーデータで埋めていない。** 動いているように見せると、
デモで「その機能はもう有る」と誤読される。サイドバーでは無効表示にし、
ダッシュボードでは v0.2 の項目として名前だけ残している。

| モックの要素 | 実装 | 理由 |
|---|---|---|
| 検索 | 無効表示（v0.2） | 対応する API が無い |
| 設定 | 無効表示（v0.2） | 同上 |
| チームランキング | v0.2 の項目として名前のみ | **v0.1 に組織・テナントの概念が無い**（FR-31a の注記） |
| 週間デバッグスコア推移 | 同上 | FR-24 の推移グラフは v0.2 |
| モデル選択（Socra-4o） | 言語 / FW の選択に置き換え | モデルはサーバが役割ごとに出し分ける（利用者は選ばない） |
| 添付 / 音声入力 | 無効表示（v0.2） | 対応する API が無い |
| プロジェクト選択モーダル | 未実装 | 演習モード専用。v0.1 のスコープ外 |
| Tailwind CDN / Google Fonts | 使わない | 外部ホストへの依存を持ち込まない（ADR-012 / #23 の細い回線での計測） |
