前提 — リスクを直視する

エラーログには API キーや接続文字列が日常的に混入します。 「混入する前提」でシステム側が守る設計です。 「ユーザーが気をつける」では解決しません。

R1入力に認証情報が混入する
R2入力が外部の LLM プロバイダに送られる

秘匿情報の自動マスキング(R1)

保存前・LLM 送信前に自動マスク。クライアントとサーバの二段構成で同じ関数を実行します。

ブラウザ ─ ① 貼り付けた瞬間にマスク ② 結果をプレビュー表示(送信前に確認) └ マスク済みテキストのみ送信 サーバ ─ ③ マスキングを再実行(ここが正) ├▶ データストアへ保存 └▶ LLM へ送信

プレビューで見た内容と実際に送られる内容がずれません。生のテキストはブラウザから外に出ません。

自動で検出・マスクするもの

API キー類sk-, ghp_, AKIA 等 → [REDACTED_KEY]
Bearer トークン / JWT[REDACTED_TOKEN] / [REDACTED_JWT]
接続文字列の資格情報[REDACTED_CREDENTIALS]
メールアドレス[REDACTED_EMAIL]
ローカル絶対パスファイル名より前をすべて伏せる(中間の顧客名・プロジェクト名も残さない)
登録済みの社名・製品名[REDACTED_NAME]
正直にお伝えします — 未登録の顧客名などの固有名詞は自動では検出できません。 そのためマスク結果を送信前にプレビューで表示し、利用者自身が確認・修正できます。 何をしていて何を保証していないかを明示する方針です。

LLM プロバイダへの扱い(R2)

学習利用ゲートウェイ側で学習に使わせない設定を確認・明記
送信内容マスキング済みテキストのみ。氏名・メールは送らない

API キー・認証・ログ

API キーブラウザに出さない。実行環境の環境変数のみ(リポジトリ・CI にも置かない)
登録招待コード必須(無制限サインアップを置かない)
パスワードソルト付き scrypt でハッシュ化
他人のデータキーに所有者 ID を含む構造。他人のセッション ID では「存在しない」しか返らない
ログエラー本文・コード断片を残さない。記録はトークン数・コスト等のメタ情報のみ

濫用への防御

レート制限セッション作成 10 回/時/ユーザー
トークン上限1 セッション 80,000 で打ち切り
冪等性API 直叩きでも LLM を連打させられない
XSS / 通信LLM 出力を HTML として描画しない / すべて HTTPS

v0.1 で未対応(v0.2 で対応): マルチテナント・監査ログ / SSO / パスワードリセット。 やっていないことを「やった」とは書きません。
